# Database Migration - 2024-11-21

## Parent System Updates

### Overview
This migration updates the database schema to support the new parent dashboard system implemented on November 21, 2024.

### Changes Made

#### 1. Parent Entity Updates
- **Changed `user_id` field type** from `integer` to `uuid` to properly reference the users table
- **Added foreign key constraint** to ensure data integrity between parents and users tables
- **Added performance indexes** for parent dashboard queries

#### 2. Performance Optimizations
- Added indexes on frequently queried fields:
  - `parents.user_id`
  - `student_parents.student_id`
  - `student_parents.parent_id`
  - `schedules.group_id`
  - `weekly_session_plans.group_id`
  - `student_progress.student_id`

#### 3. Data Consistency
- Updated existing parent records to ensure valid user references
- Set invalid user_id references to NULL
- Ensured all parent users have the correct 'parent' role

#### 4. Sample Data
- Creates a test parent user if none exists (for development/testing)
- Links the test parent to a parent record

### Files Created
- `2024-11-21-parent-system-updates.sql` - The migration SQL script
- `run-migration-2024-11-21.js` - Node.js script to run the migration
- `README-2024-11-21.md` - This documentation file

### How to Run

#### Option 1: Using Node.js Script (Recommended)
```bash
cd school-management-backend
node scripts/run-migration-2024-11-21.js
```

#### Option 2: Direct SQL Execution
```bash
cd school-management-backend
psql -h localhost -U postgres -d zinat_al_haya_db -f migrations/2024-11-21-parent-system-updates.sql
```

### Verification
After running the migration, verify:

### Rollback (if needed)
To rollback this migration:

```sql
-- Remove indexes
DROP INDEX IF EXISTS idx_parents_user_id;
DROP INDEX IF EXISTS idx_student_parents_student_id;
DROP INDEX IF EXISTS idx_student_parents_parent_id;
DROP INDEX IF EXISTS idx_schedules_group_id;
DROP INDEX IF EXISTS idx_weekly_session_plans_group_id;
DROP INDEX IF EXISTS idx_student_progress_student_id;

-- Remove foreign key constraint
ALTER TABLE parents DROP CONSTRAINT IF EXISTS fk_parents_user_id;

-- Revert user_id type (if needed)
ALTER TABLE parents ALTER COLUMN user_id TYPE integer USING user_id::integer;
```
